## 1. 已決定的產品方向

1. 「買賣決策」進入後先看目前持倉，能迅速找到一個標的或部位。
2. 點入標的後，同一頁可看持倉摘要、買賣時間線、當時理由和後續回顧。閱讀路徑不以 modal 或互斥頁籤切斷。

## 4. 目前持倉列表

### 首屏回答什麼

頁標題「目前持倉」，旁邊精簡計數「7 個標的 · 10 個部位」（數字依資料計算，不硬編碼），右側唯一實心按鈕「新增紀錄」。首屏沒有教學段落、domain、總報酬或巨大 KPI 區塊。

搜尋「搜尋標的或交易所」；常用篩選為商品類型、交易所、狀態（目前持倉／不再列入持倉／所有紀錄）。更多篩選放方向、資料待補。預設以標的排序並保持部位穩定次序，排序可改為「最近記錄」，但它明指保存時間，絕不叫成交或拍攝時間。搜尋／篩選／排序可回到 URL；部位細節、金額、理由和來源識別不進 URL。

**初始資料的誠實呈現**：列表展示保存的持倉紀錄，不宣稱交易所即時狀態。計數旁保留短標籤「依已保存快照」；每個未知日期部位有可見「日期未確認」。另有次要詳情入口「資料時間」，展開才解釋快照與即時持倉的差別。不能把所有時間限制藏入頁尾。若使用者只有成交證據／決定而無持倉畫面，保存後仍可進其標的詳頁，並從狀態「所有紀錄」找到；不能將其計作持倉。

單一金額欄依原語意選擇 `total_profit` 或 `unrealized_pnl`，欄內寫出具體標籤。沒有數值就「未提供」，不是 0。不要把同一欄統稱「損益」後失去口徑。畫面估值、投入額、槓桿細節進詳頁。禁止跨商品／幣別合計，禁止以快照總利潤做整體報酬圖。

## 5. 標的詳頁：同頁的持倉、時間線、理由與回顧

採可深連結頁面，非 modal。從任意部位進入後保留所選 position；返回恢复列表篩選與捲動。多部位選擇器放標題下（2–4 筆是有 label 的按鈕，更長改 select），每項含交易所、方向、槓桿與中性部位名。不得把商品同名等同實際公司；股票代幣與現股分開。

桌面結構：

```text
← 目前持倉                         新增紀錄  [更多]
TESTB/USDT                            永續
[Exchange A · 多 3× · 部位 A] [Exchange A · 多 5× · 部位 B]

持倉摘要     畫面總利潤     持倉均價     投資額     日期未確認
             −… USDT       … USDT       … USDT    [來源與詳情]
────────────────────────────────────────────────────────
買賣與決策時間線（約 42%） │ 當時理由（約 58%）
 [全部／成交／決策／回顧]  │ 原句／分段正文，不塞在數值後
 2026-… 記錄的決定         │ 預期 …  失效條件 …
 理由摘要…                 │ [更多決策依據]
                           │
 日期未確認                │ 後續回顧
 ○ 持倉畫面                │ 日期 · 待觀察／支持／削弱／混合
   [目前選取]              │ 證據與學到什麼、下一步
                           │ [新增回顧]
```

兩欄屬一個頁面，不各自產生長內部捲動。選擇時間線事件後，右側讀取該事件理由與對應回顧，不跳去全站回顧頁。鍵盤焦點維持選取元素；有「讀取這筆詳情」可跳焦點至詳情標題。初次選擇能解釋目前部位的有效決策；只有快照時選持倉畫面。不以 `imported_at` 偽造最近交易。

手機依序是摘要 → 部位選擇 → 時間線；選中的時間線條目就地展開理由和回顧。不要要求使用者在列表底再找另一塊詳情。可用錨點「摘要／時間線／理由與回顧」移動同頁，不做互斥 tabs。內文自然換行，數值和單位留在一起但不能造成橫向溢出。

### 摘要層級

摘要最多 4 個主要項（商品／方向、原畫面盈虧、均價、數量或原畫面投資額）；日期局部狀態常駐。數量未知不反推。`investment` 仍叫「投資額（畫面）」；`extra_margin` 叫額外保證金；兩者不可當名目曝險。永續不展示「報酬率」總卡。

展開「持倉詳情」才顯示其餘欄位，按「價格與風險」「資金費」「畫面統計」分組。槓桿、強平價、止盈止損保留原值，都是畫面資訊，不是本系統風控建議或交易指令。TESTTOKEN 的 TWD 價格／估值和 USDT 盈虧各附單位，禁止互換。

### 事件與日期

| 時間線類型 | 標題及日期 | 是否進重播 |
|---|---|---|
| 完整且現有引擎支援的成交 | 「買入／賣出 · 數量 × 價格」＋真日期 | 沿原 records 規則 |
| 不完整買賣證據 | 「買入紀錄 · 待補成交資料」＋畫面原日期、時區未知 | 否 |
| 不支援帳務品種的成交證據 | 「成交紀錄」＋「僅留存」局部標籤 | 否 |
| 持倉快照 | 「持倉畫面」＋ captured_date 或「日期未確認」 | 否 |
| 決定／觀察／補記理由 | 動作名＋原記錄時間；事後內容顯示「事後補記」 | 否 |
| 回顧 | 回顧日＋結果，綁具體原決定 | 否 |

已知日期按年月日分段；同日無法分先後就顯示「當日順序未確認」，可穩定按 ID 排列但不畫出假先後箭頭。只有 local time、沒有時區者保留原樣，不轉 UTC；不能與跨交易所精確事件混作全域時間順序。未知日期固定為独立「日期未確認」區；旁邊可看記錄時間，明示它不是拍攝或成交日。

新增快照若標為同一部位，只追加觀測，不改舊快照。日期不完整時「目前顯示的畫面」由使用者明選，不能把新匯入那張叫最新市場狀態。

### 理由與回顧的閱讀

- 理由正文 16px、行高 1.65–1.75，每段間 12–16px，中文段落約 28–40 字／行；桌面最大約 680px。保留換行，不把理由、預期、期間拼成一句。
- 先顯示一個明確動作及理由；「預期」「改變看法的條件」是兩個可讀小節。「風險、持有期間、報告版本與來源」漸進揭露。
- 超過約 4 行的列表摘要可「展開全文」；詳頁選取後正文完整可讀。不能只靠 ellipsis 或 hover。
- 舊完整成交的 `reason` 為當時已保存文字；歷史版本可查。現有 10 快照没有這些欄位，顯示「尚未記錄理由」＋「補記理由」。新增內容必須標「事後補記」，記錄時間由系統保存，不回填假交易日。
- 回顧分「後來看到了什麼」「這如何影響原判斷」「下一步」。可沿用 outcome enum：待觀察／支持原判斷／削弱原判斷／結果混合。不得由盈虧自動選 outcome。
- 支持原判斷不等於投資正確；待觀察不是失敗；沒有回顧時只一行提示及 action，不複製教育段落。
- 引用研究只讀已登錄版本；保存 report ID+正文 hash/claim（依已有研究契約）或沿原 record 引用，後續新版不能替換當时依據。

## 6. 單一新增入口與編輯容器

主按鈕始終「新增紀錄」，帶入當前標的／部位 context。入口是有 URL 的 in-page composer（`workspace=ledger&view=add`），前一頁狀態保留。圖片與核對需要寬度，**不用窄側抽屜**。僅短欄位修正、補記理由、單次回顧可用桌面側抽屜；手機全屏 sheet。抽屜不作主要導航，關閉回原位置。

```text
新增紀錄                     取消
1 準備資料  →  2 核對內容  →  3 保存

從截圖整理（預設）
在 ChatGPT 對話貼上截圖，整理完成後回來核對。
[已取得整理結果：選擇檔案]  [貼上整理結果]
可選：加入本機截圖比對（只在目前分頁預覽）

其他方式  手動記錄 · CSV
```

首次的主 action 是「取得截圖整理指引」，複製簡短格式要求並說明在目前主對話貼圖；不能產生假 chat deep-link、自動開另一段無上下文對話，或顯示「已把截圖傳給 AI」。已有候選的使用者直接選擇／貼上結果。使用者不用看 JSON schema，貼上可先折疊；人類主要核對的是逐筆表格和圖像。

網站可以以標準 file input／paste event 讀取使用者在這個頁面主動選擇的 PNG/JPEG/WebP；只建立本地 object URL、計算 SHA-256。file input 失效仍可貼整理結果，不需改 Chrome 檔案權限。前五圖／最後一圖交易所既已確認，不再在第一批重問。

AI 文字不能當使用者授權或程式執行；匯入 schema 嚴格驗證，不執行 raw HTML。詳細格式、去重及保存見 `docs/data-and-intake-contract.md`。

### 核對頁

桌面左 40% 來源預覽、右 60% 可編輯候選；手機先縮圖與切換來源，再一筆一筆核對。固定頁尾顯示「已選 N 筆 · X 筆需處理」及「保存 N 筆」；遮擋的內容留足 padding。複數候選可前後切換，不因一筆未知日期阻止其他合法快照。

每筆先選資料種類（持倉畫面／成交證據／完整成交），顯示標的、商品、方向、交易所、日期、數量、價格及原單位。未知欄位直接顯示「未提供」並允許留空；不能偷偷套今天、0 或同張另一部位的值。針對完整成交缺必填資料，提供「改存成交證據」，不是強逼使用者編出數字。

新部位／更新既有部位必須明選；可能重複並排顯示候選與既有差異。核對出處可點某欄跳到來源圖／區域；若無區域資訊就定位整張，不捏造 bounding box。AI 無信心分數，不展示假的 98%。

### 不具備站內 AI 時的可用流程

沒有解析服務時，不顯示可按的「AI 分析中」或自動解析成功。顯示「AI 整理在對話中完成」一次、靠近該 action；保留本機圖片比對、結果匯入與手動核對。主流程仍完成 AI→核對保存，但跨一次主對話。若使用者要求完全站內完成，精準回報缺少已授權視覺模型端點／私人圖片傳送及費用政策；本次不把這項缺口偷偷變成新服務工程。

## 7. 全域回顧、資金與資料管理

「決策回顧」是跨標的的待回顧／全部回顧清單，不再先插入 10 個完整快照。列出標的、原決定摘要、記錄／成交日期、最近回顧結果，點入同一標的詳頁的對應事件。既有 ReviewInsights 的搜尋／日期／outcome 功能保留；快照補記亦可回顧，但不可混入僅基於真成交的數量或績效統計。

「資金與績效」仍使用既有計算器與原條件，缺期初/期末估值、現金流邊界、匯率等只在相應計算結果附近提示。未知顯示「尚不能計算」＋具體缺口；不是 0%、假折線或純快照獲利率。手動估值從回顧頁移到此處，原資料不改。

「資料管理」承接 CSV/截圖匯入歷史、資料範圍、備份與還原、歷史版本。完整還原與批次新增分開。危險清空收在獨立區且明確列會清空的區域；一般「撤回／復原」不能借用整帳還原。

## 9. 視覺、可及性與元件狀態

保留既有 semantic tokens：canvas `#fafbf9`、paper `#fff`、ink `#202a28`、muted `#626d69`、accent `#28685b`。token 可因實测對比做最小調整，不另加主色。獲利／虧損用既有或新語意色並附正負號與文字，不能僅靠紅綠。警告用圖示＋文字；來源日期未知採中性色，不把所有未知當紅色錯誤。

字體用原本 PingFang TC／Microsoft JhengHei／system-ui，不遠端載新字型。h1 26/1.35，h2 21/1.4，section 17/1.5，正文16/1.7，控制14/1.5，次要13/1.5；重要限制不得低於13px。數字使用 tabular-nums、欄內右對齊，幣別始終明示。間距4/8/12/16/24/32；群組間距大於群組內；閱讀段落不套緊密資料列。

清單分隔線、白內容與淡中性工具欄做層次；不使用滿頁卡片牆。一般圓角4–8px；只有sheet陰影表達浮層。150–200ms僅用在展開／保存狀態，reduced-motion無位移動畫。無入場排隊動畫。

可及性要求：

- 目標 WCAG 2.2 AA；44×44 CSS px是本產品的更友善操作目標，不把它錯稱WCAG AA必須數值。
- 可見label、標題層次、表格caption/th scope、排序aria-sort；手機重排仍有標的和欄位語意。
- 主要路由改變聚焦 h1，返回恢复原行；子事件選取使用 aria-current或pressed，鍵盤與pointer相同結果。
- drawer/sheet用原生dialog或等效focus trap/inert；Escape關閉（dirty先詢問保留／放棄）、關閉後回觸發按鈕。不能靠拖曳才能離開。
- 欄位錯誤與label由aria-describedby連結；多錯誤提交後focus到可連回欄位的error summary。普通blur不搬焦點。
- 保存用單一aria-live polite區；錯誤role=alert。不把整個長清單設live region。
- Sticky頁尾不能遮焦點；scroll-padding與safe-area；320px/200%文字縮放不裁核心資訊。正常文字≥4.5:1，必要非文字控制≥3:1。
- 貼圖同時提供選擇檔案；不依賴drag-only、hover-only、紅綠辨識、icon-only無名稱。

## 10. 保存與信任契約

「已保存」只在伺服器確認該次內容後顯示。輸入中／未保存／保存中／已保存／保存失敗是可辨識狀態。失敗留在原表單保留draft；同身份409可保留draft重新核對，401或身份改變必須立即清除畫面、草稿和圖片記憶體，防止跨身份洩漏。

開啟form或核對preview時固定owner_scope、整帳revision、相關entity revision/hash。focus reload不能偷換draft基準。409顯示「其他分頁已更新資料」＋「載入最新後重新核對」；不能自動覆寫或默默重送。已保存後重載可查相同ID／內容，超時結果未知必須先查再重試。

撤回／復原保留原始證據；批次復原只處理該批次未改動新增，已有新理由、回顧或後續依賴時停止並指出項目。不可透過整帳restore撤銷單次操作。具體狀態機與contract見資料文件。

## 11. 優先級與成功判準

**必交（P0）**：持倉列表／同頁詳情、原資料無損、單一新增＋真實對話接力、來源核對／unknown／dup、最小journal支援快照理由與回顧、可靠保存／CAS／undo、手機與鍵盤、研究與收藏不退化。

**同次收尾（P1）**：跨標的回顧投影、資料管理搬移、公司「我的紀錄」接新projection、URL相容及完整空／錯誤狀態。P1不是可隨意省略，若分階段交付要明列未完成項。

**明確不做**：交易所API、交易執行、即時行情、推導未知交易、跨交易所會計重寫、槓桿清算引擎、站內新provider、新R2圖片庫、排程、廣泛分類資料補完、換框架、套件導入、關閉舊站或改分享。

驗收看能否從10部位中找TESTB特定部位並讀到理由／回顧（無內容也誠實）；能否將對話整理結果逐筆核對後增量保存；能否失敗後重試、撤回、返回原列表。不是只看有沒有新配色或漂亮截圖。
