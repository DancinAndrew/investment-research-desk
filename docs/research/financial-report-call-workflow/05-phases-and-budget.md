# 分期、最小示範與成本控制

所有階段均待使用者另行同意開發。本次只交文件；不啟動清單中的導入、推論、API、排程或部署。

## 分期与出口條件

| 階段 | 具體工作包 | 出口條件 | 不依賴 |
|---|---|---|---|

先做P0a才估P0b/c工程時間：解析品質、舊兩季Q&A權利及資料體积仍未實測，不能用文檔页數保證工期。以可審閱資料包為中間交付，不等整套平台完成才讓使用者看到結果。

## NVDA最小示範範圍

範圍固定FY25Q3、FY25Q4、FY26Q1–Q4、FY27Q1–Q2，以2026-10-12公開資訊為上限。release/CFO/申報為主幹，transcript只有六季入口已確認。示範不重做全公司深研，也不把既有NVDA v6文字重新包裝成八季追蹤。

- 財務：8季營收、毛利／率、營益／率、GAAP diluted EPS及必要股數；CFO、CapEx與FCF依披露口徑。沒有單季原值時可比累計推導並標來源，不推EPS相減。
- 管理層：五類主題全做候選檢查；收斂12–20個對原thesis重要的主張，5–8個有可核deadline/KPI的目標。數量不足時如實列少，不抽象發言硬造目標。
- 變化：至少含一個數字或期限變化、一個口徑變更、一個缺件／不可比；不能保證會找到真實營運惡化或矛盾。用資料已知的non-GAAP SBC定義變動驗可比性。
- 產物：coverage、normalized facts、claims/targets、evidence links、outcomes、change candidates、accepted assessment、一頁摘要、三個追蹤問題、重算／審查收據。原先研究模型與判斷保持原hash。
- 明確排除：8季完整第三方稿重新發布、真持倉、ASR付費、價格／法人流、自动通知、推論勝率。AMZN仍為替代候選，本輪未再查八季官方來源，換標的需先補coverage。

## P2的月度紀律

月度thesis先凍結四軸基線，只有新证據可以產生更新候選。來源晚於月底的內容列後續事件，不能倒填。研究者分別記「事實判錯、因果不成立、期限延後、估值／機會成本改變、資料不足」等改判理由；分類可多選並附原句。賺錢也可能與原論點無關，虧損也不能單獨證明生意判斷錯。

月度review依研究重要性和可解程度排工作，不按資料好抓或聲量排序。每項工作有一個能被回答的問題、一個優先一手來源、完成標準與截止；保留前月未完成原因。沒有自動生成使用者信念或閱讀進度。

## P3規則示例（設計假設，非已驗策略）

先定義 `adjustment_basis`、交易所日曆、收盤／盤中、資料延遲、公告可用時間。候選條件可為當日成交量／前20交易日成交量中位數>2、五日相對指數報酬偏離、法人淨買賣占已披露成交量比率，及公告前後事件窗；門檻是示範，必須在檢查區間前凍結，評估誤報和多重篩選偏差。

缺20個有效交易日不算基準；除權、拆股、停牌、價格限制及不同交易時段需標記。公告後異常與公告造成異常分開；相對報酬只是描述，不是因果估計。三大法人分類不代表同一意圖或「主力」，淨買額也不是持倉或終端需求。

基本面規則另有確認條件，例如「下一次正式公告的同口徑收入／毛利符合原target」；失效條件應來自原thesis，例如「指定產品未在原期限完成驗證且已由公開原件確認」。價格觸發只建立人工核對候選，不直接判基本面好坏。

## 成本与token控制

以下是**未来P0首輪的規劃上限**，非本次實際用量或模型報價。先用一季量測，再確認是否需要調整；不能為守上限偷偷截斷並宣稱全文已讀。

| 工作 | 输入token上限 | 输出token上限 |
|---|---:|---:|
| 8季逐季抽取，含必要上下文 | 8×18,000＝144,000 | 8×2,500＝20,000 |
| 跨期對齊與有界摘要 | 24,000 | 6,000 |
| 獨立語義／反方覆核 | 20,000 | 4,000 |
| 基本合計 | 188,000 | 30,000 |
| 含20%重試reserve的硬上限 | 225,600 | 36,000 |

所有agent、工具上下文、cache miss與重試均算入run；tool內部計費若有也另記。合計估費公式是 `(uncached_input×rate_in + cached_input×rate_cached + output×rate_out)/1,000,000 + ASR_minutes×ASR_rate + data_fees + runtime_storage`。本輪沒有替未選定的文字API填價格，Codex共享訂閱用量不能換算成單任務現金費用。

八季歷史初始化後，每新季原則只解析新文件、受影響前期重列及相關claim；快取key包含source hash、parser、schema、prompt、model，不靠檔名。達80%預算顯示剩餘工作；達100%停止並保存partial與gap，使用者另決定範圍或加額。單job預估费用、月預算、最大並行和重試次数在啟用API前必填；金額未核准時付費API budget=0。供應商的soft alert不能當硬限額，runner本身需預檢／記帳／停止。

本機也有人工時間成本，記錄來源取得、數字勾稽、主張覆核與修正時間。ASR便宜不能代表核數字／講者便宜。成效用「同品質下少花多少核對時間、重大引用錯誤率、未支持主張率、缺口揭露率」衡量，**不是股價漲跌或賺錢率**。

4. 接受資料包、介面驗收、正式發布分開；發布維持既有私人部署且須後續當次授權。沒有源碼或部署權限時仍可完成本機研究包，不假稱已上線。
